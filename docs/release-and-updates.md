# Релизы и обновления

`release.yml` запускается при изменениях приложения в `master` или вручную. Автоматический выпуск повышает patch-версию от последнего тега `manager-workspace-vX.Y.Z`; вручную можно выбрать minor или задать SemVer. Исходная версия в Git остаётся базовой. Заметки обязательны для каждого выпуска и дописываются в `CHANGELOG.md`; генератор сравнивает его с последним тегом, готовит двуязычный текст релиза и встраивает каталог в приложение. Если новых записей нет, сборка останавливается.

CI последовательно собирает macOS Apple Silicon, macOS Intel и Windows x64. Пакеты и подписанный Tauri updater manifest публикуются сперва как черновик. Публичный релиз появляется только после проверки всех трёх платформ в `latest.json`; незавершённый выпуск удаляется. Проверка в приложении выполняется в фоне при запуске и раз в сутки, с таймаутом 10 секунд. Установка начинается только после нажатия «Обновить». Заметки после установки читаются из локального каталога и работают без сети. Первый запуск сохраняет текущую версию без модального окна; окно появляется после обновления только если в новой версии есть записи.

## Настройка подписи перед первым выпуском

В `.local/signing/manager-workspace.key` создан приватный ключ Tauri; каталог исключён из Git. **Сохраните защищённую резервную копию этого ключа** и добавьте его содержимое в секрет GitHub Actions `TAURI_SIGNING_PRIVATE_KEY`. Публичная часть уже добавлена в `src-tauri/tauri.conf.json`. Потеря приватного ключа лишит установленные копии возможности получать обновления с этим публичным ключом. Пароль пустой; `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` не нужен.

macOS без Apple Developer ID собирается с ad-hoc подписью и может потребовать «Open Anyway» при первой установке. Для Developer ID и нотариализации нужны `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_API_KEY`, `APPLE_API_ISSUER`, `APPLE_API_PRIVATE_KEY_BASE64`. Windows Authenticode здесь не настроен. Не включайте публичный релиз, пока не проверите установку пакета и обновление на нужных ОС.

Для локальной проверки заметок выполните `node scripts/build-release-notes.mjs 0.1.0`. Команда обновляет `src/release-notes/generated.json` и создаёт временные файлы в `.release/`; перед PR верните `generated.json` к `{"releases":[]}`, поскольку CI создаёт каталог для каждой версии отдельно.
