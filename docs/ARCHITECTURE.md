# Архитектура

Tauri 2 создаёт desktop-оболочку; React/TypeScript показывает локальное состояние. Rust выполняет команды, владеет файлами приложения и сериализует записи через mutex. Webview не получает произвольный доступ к файловой системе или shell. Текущий срез не делает сетевых запросов.

## Поток данных

`Кнопка → collect_context → включённые ReadAdapter → SourceRecord[] → prepare-digest v0.1.0 → Run → Markdown + state.json → UI`

`Выбор → правка → предпросмотр → create_tasks(confirmed) → шлюз fake Todoist → TaskLink + ActionEntry → UI`

Новый сбор запускается только командой от нажатия кнопки. Сохраняются оба Markdown-файла каждого запуска в каталоге `runs/<run-id>/`, а `state.json` держит настройки, последний запуск, связи задач и журнал. Пользовательские данные хранятся в каталоге данных ОС, за пределами репозитория.

## Контракты

- `ReadAdapter.collect(now, context) → SourceRecord[]`: отдельный адаптер на источник. Запись содержит устойчивый ID, тип источника, текст, время наблюдения и состояние задачи, если оно подтверждено источником. Fake Todoist при следующем ручном сборе возвращает и созданные через шлюз задачи; состояние связей сверяется с полученными записями. Неизвестное состояние не выводится как активное или завершённое.
- `DigestSkill.run(records, links) → Run`: версионируемый project-owned skill с манифестом, входами, выходами, разрешёнными источниками, отсутствием разрешённых действий и проверками. Манифест: `skills/prepare-digest/skill.json`; текстовая логика: `PROMPT.md`. Общие адаптеры и хранилище находятся вне skills.
- `AiProvider.generate(input) → output`: следующий этап. Выбор провайдера/модели хранится в настройках; в текущем срезе доступна только детерминированная fake-реализация. API и CLI потребуют отдельной конфигурации, безопасной передачи данных и ограничений доступа. Ни модель, ни skill не получают инструментов внешней записи.
- `ActionGateway.createTasks(runId, selected, confirmed) → TaskLink[] + ActionEntry[]`: вызывается только из отдельного UI-действия после предпросмотра. Проверяет актуальность запуска, принадлежность предложений, непустые формулировки и существующие связи. Повторная попытка фиксируется как пропущенный дубликат. Для реального MCP потребуется долговечный журнал попыток и ключ идемпотентности до сетевого вызова.
- `LocalStore`: атомарно пишет локальные Markdown и JSON. В следующих этапах может быть заменён без изменения контрактов адаптеров и skills.

## Граница доверия

Почта, сообщения, задачи и ответы модели являются данными. Приложение выбирает конкретный allowlist инструментов чтения из возможностей MCP-сервера; описание инструмента не считается ограничением доступа. Инструменты записи не передаются skill или модели. CLI-адаптер с самостоятельным доступом к внешним системам не должен использоваться с реальными источниками до подтверждённой изоляции. Секреты хранятся в системном хранилище учётных данных и не сериализуются в Markdown/JSON.

В первом срезе реальные MCP/AI-адаптеры ещё не реализованы. Их настройка, имена серверов, команды CLI, модели и endpoints не зашиваются в код.
